# 0002: Semver releases with semantic-release

**Status:** Accepted, November 2026

## Context

Changes reach production when `develop` merges into `main`, but nothing recorded which version of the site was live or what changed between deploys. Commits already follow Conventional Commits, so the information for a changelog is in the history.

## Decisions

- **semantic-release on every push to `main`.** It derives the next semver version from the commit types since the last tag (`feat` → minor, `fix`/`perf` → patch, breaking change → major), pushes a `vX.Y.Z` tag and publishes a GitHub Release with notes generated by the `conventionalcommits` preset. The committed resume PDF is attached to each release, so every version of the resume stays downloadable.
- **No commits back to `main`.** The release doesn't bump `package.json` or write a `CHANGELOG.md`. Both `main` and `develop` are protected, and a bot commit on `main` would have to be merged back into `develop` after every release. GitHub Releases are the changelog; tags are the source of truth for the version.
- **Release from `main` only.** `develop` is an integration branch, so there are no pre-release channels.
- **commitlint in CI on every pull request.** A mistyped commit type would silently skip a release or pick the wrong bump, so commit messages are checked before they can merge. Merge commits are ignored.
- **Tools pinned as dev dependencies** rather than run with `npx <tool>@latest`, so the lockfile fixes their versions. `conventional-changelog-conventionalcommits` stays on v9 until semantic-release's notes generator supports `conventional-changelog-writer` v9 (v10 of the preset needs it).

## Consequences

- The first release is `v1.0.0` and its notes cover the whole history up to it.
- Content updates should use `feat:` (new or changed content) or `fix:` (corrections) so they produce a release. `docs:`, `test:`, `ci:` and `chore:` commits ship with the next release but don't trigger one.
- Squash-merging a PR would collapse its commits into the PR title, so PRs keep using merge commits.
